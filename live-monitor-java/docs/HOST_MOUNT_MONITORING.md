# 主机挂载点监控

在「服务器主机 → 编辑主机」勾选「挂载点监控」，每行填写一个实际挂载点，例如 `/`、`/data`、`/backup`。可先点击「预览挂载点」验证，再保存。新功能默认关闭，升级不会自动修改已有主机的监控范围。

检测范围：

- 挂载丢失：路径不在主机挂载表中。普通目录仍可访问、落到上层文件系统时也判为丢失。
- 只读：挂载选项或文件系统选项包含 `ro`。
- 空间超阈：该挂载点使用率大于主机的磁盘阈值，默认 85%。挂载点监控独立于原磁盘告警开关。
- 未知：挂载表、容量数据不可用或尚未采集；不会用 0% 代替未知数据，也不会将采集失败直接当作卸载。

不校验预期设备是否变化，不写测试文件，不执行挂载、卸载或修复磁盘命令。明确配置的网络文件系统同样可以检查；底层 SSH 采集仍受超时限制。

主机列表新增挂载点状态，指标详情新增挂载点表，显示设备、文件系统、总容量、可用空间、使用率和检测原因。告警复用当前主机的告警组及通知队列、异常确认、恢复确认和冷却策略。同一挂载点的同类异常需连续达到确认样本数；采集未知时不判为恢复。对同一主机的资源异常沿用现有聚合状态。只有配置了恢复通知规则及有效接收渠道才发送恢复消息。

## API 与数据库

已有 `/api/hosts` 创建、列表、详情和更新接口新增：

```json
{
  "mount_monitor_enabled": true,
  "mount_points": ["/", "/data"]
}
```

`mount_points` 最多 64 项，须为绝对路径；去重并规范末尾斜线，不允许控制字符和 `..` 路径段。更新时省略新增字段会保留已有设置。

`POST /api/hosts/mount-preview?host_id=1` 接收完整主机配置（同创建/更新字段）。编辑时可复用已有 SSH 凭据，留空不覆盖密码。只读返回挂载点检测结果，不保存配置、指标历史或告警；新增主机预览可省略 `host_id`。

指标及历史的 `disk_metrics` / `disk_metrics_json` 中，所监控挂载点包含 `monitored_mount: true`、`mounted`、`read_only`、`mount_state` 和 `mount_reason`。状态值为 `OK`、`MISSING`、`READ_ONLY`、`HIGH_USAGE`、`UNKNOWN`；未知容量、挂载状态不伪造数值。历史随现有主机指标一起保存和清理。

启动迁移为 `host_config` 新增 `mount_monitor_enabled INT DEFAULT 0`、`mount_points_json TEXT`，同时更新 MySQL / H2 初始化脚本；不删除或重建已有表。通知事件新增 `HOST_MOUNT_ABNORMAL`，发送任务继续使用原有持久化队列。

## 验证

201 项 Java 测试及 51 项浏览器测试通过，涵盖配置持久化和省略字段兼容、路径校验、挂载丢失、只读、空间超限、采集未知、连续确认、通知去重与恢复、只读预览和页面回显。
