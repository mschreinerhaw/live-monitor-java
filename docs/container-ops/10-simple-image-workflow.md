# 简化镜像部署与运行监控（2026-10-25）

## 现状与增量方案

现有 Vue3 使用 vue-router、项目自有组件与 CSS，统一 `OpsPlatformView` 调用 `useOpsPlatform`；顶栏和侧栏重复提供监控导航。现有 Java Spring Boot 运维模块通过固定命令 SSH Agent 执行白名单 Docker 操作，复用登录、服务器/环境/动作授权、异步任务、SSE、任务审计及版本备份。原先镜像操作依赖已批准仓库及 Digest，缺少用户上传离线镜像包的链路。

保留原监控及高级运维，默认侧栏收敛到运行监控、镜像与上传、我的应用、告警、操作记录。顶栏保留身份与通知，移除重复业务导航。服务器、远程仓库、应用栈、恢复、权限等放入折叠入口。新增 `ImageLibraryPanel` 与 `QuickDeploymentPanel`，复用原部署、健康监测、人工停机、熔断与受控回滚，不重写监控系统。

## 用户操作

1. 首次使用，在“高级运维 → 服务器管理”连接受管服务器。主机管理员安装 Agent 并明确批准 `allow_image_import: true`；SSH 主机公钥须可信核实。后续上传部署均在页面操作。
2. 在“镜像与上传”选择服务器，上传 `docker save` 导出的 `.tar`、`.tar.gz` 或 `.tgz`；平台后台校验并导入 Docker，压缩包由 Docker 自动解压，不将任意归档路径解压到主机。
3. 在镜像列表点击“部署 / 更新应用”，填写名称和访问端口。可选择更新已有应用，沿用环境、挂载、密钥引用及资源配置。页面先校验，再异步部署，任务展示中文阶段和失败原因。
4. 在“运行监控”查看服务、资源、告警和恢复状态，并启动、停止、重启。更新版本从镜像列表选择新镜像，再选择已有应用。版本历史与受控回滚保留。

镜像声明的端口和健康检查作为提示，不按业务名称推测参数。有健康检查时使用镜像声明的命令；没有时明确使用容器进程监控，不注入 `true` 伪装应用健康。持久化目录必须确认挂载；更新有状态应用前需确认备份和数据兼容。

## 后端与安全

- 新增 `ImageArchiveService` 与 `POST /api/ops/images/import`，复用交互会话、同源头、主机/环境 `import_image` 权限和明确发布确认；普通 operations 接口不能传入本地归档路径。
- 文件落盘并流式计算 SHA256，任务只存受控暂存路径和摘要。通过既有固定命令 SSH 通道传送 JSON 头和原始字节，不开放 Docker TCP，不依赖任意远程 Shell/SFTP 路径。
- 默认文件上限 4 GiB，可通过 Spring multipart 与 `live-monitor.ops.max-image-archive-bytes` 配置；暂存目录可配置，队列有界。实际执行结束清理暂存文件。中断控制器后残留文件需结合任务记录核对，不盲目重试未知结果。
- Agent 再次校验环境、主机批准、大小、磁盘、摘要、Docker-save manifest、归档路径/链接、成员数量及解压总量。默认解压内容上限 20 GiB；镜像包不是任意业务压缩包或完整应用备份，也不自动执行包内脚本。
- 导入镜像以配置内容 SHA256 固定版本，记录在当前环境的 Agent 导入目录；仅该环境已导入的本地 ID 可用于部署，不能任意指定主机已有镜像 ID。远程仓库仍使用原批准 Digest 路径。
- 自动恢复继续遵循原策略：人工停止优先，Docker 原生退出恢复与平台 unhealthy 恢复协作，保留退避/熔断及审计。端口可访问性取决于主机 `publish_address` 与防火墙，页面不自动修改防火墙。
- 不新增数据库表，复用 ops_task/resource/audit/event、既有迁移机制和 SSE。业务参数不硬编码到 Vue。
