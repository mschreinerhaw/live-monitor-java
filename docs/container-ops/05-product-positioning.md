# 统一镜像部署、运行监控与故障恢复平台

## 产品定位

面向多台服务器、多套应用、多环境提供统一控制面。原监控系统继续负责已有服务和数据采集；新增容器运维模块管理发布、运行状态、备份和故障恢复的完整生命周期。

## 资源模型与职责

| 对象 | 管理内容与边界 |
|---|---|
| 服务器 / 分组 | 引用现有加密 SSH 凭据，绑定经核验的主机公钥；独立连接、任务锁和采集快照 |
| 环境 | 主机及其 Agent 明确绑定环境，应用、容器和卷均核验环境；跨环境发布建立独立应用记录 |
| 应用 | 独立部署配置、运行意图、恢复策略、活动版本和历史；同一服务器可部署多套应用 |
| 镜像仓库 | 仓库白名单、TLS 校验、Agent 本地凭据引用；Tag 解析为内容 Digest 后发布 |
| 版本 | 记录 Digest、命令、参数、资源、端口、卷、健康策略和 Secret 引用，用于审计与受控回滚 |
| 任务 / 事件 | 持久异步任务、幂等、进度、结果、SSE、失败原因及授权审计 |
| 备份 | 区分配置、持久卷和数据库；恢复演练后恢复到新目标，保留原数据 |

运行意图和观测状态分离：用户停止应用时先记录 STOPPED；采集的异常状态不能覆盖停机意图。自动恢复还受维护状态、持续故障窗口、原生 Docker 重启策略、退避和熔断约束。状态变更后的旧采集样本不能再次触发恢复。

## 多服务器与环境隔离

平台统一查询多个服务器，任务按主机互斥、跨主机独立执行。离线服务器的连接超时和失败保存在自己的任务与告警中，不阻断其他主机。采集快照和历史任务回执按应用的主机归属过滤。

授权按服务器、环境和操作类型判断，执行异步任务前再次校验。新增范围账号默认只能使用授权的运维 API，不能借用旧监控接口获得更大的管理权限。前端不持有 Docker 高权限身份，Agent 通过固定命令和加密 SSH 通道访问本机 Unix socket。

当前每个受控 Agent 绑定一个环境。不同环境应使用独立服务器或隔离的 Agent 执行域，不能只修改页面上的环境名称。统一管理不意味着自动接管服务器上已有容器；只有显式登记并经平台发布的应用进入恢复闭环。

## 部署与验证原则

2026-10-25 用户授权将完成的版本部署到服务器验证。首次部署使用独立验证实例、独立数据目录和私有访问入口，不替换旧监控服务或 ChatChat 生产容器。公网 Docker TCP 始终关闭；默认管理员密码在开放访问前更换。

本次已知授权目标是一台物理服务器。多主机并发、离线隔离和环境授权已有本地测试证据；服务器验收报告必须如实记录实际物理服务器数量，不将同机多个应用称为多台服务器验收。
